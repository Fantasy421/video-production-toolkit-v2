# Video Production Toolkit V2 设计规格

## 1. 项目定位

`video-production-toolkit-v2` 是一个独立目录、独立 Git 仓库和独立 Codex 插件。它面向需要快速完成知识视频、口播视频和图文动效视频的用户。

V2 的核心目标是主动提出有依据的推荐并引导用户完成选择。AI 根据内容目标、受众、平台、配音时长、素材条件和制作成本，先给出可直接接受的推荐方案；用户只需在少量关键节点确认或调整，媒体生产则交给按批次工作的专用 Agent。

## 2. 产品目标与边界

### 2.1 目标

- 让每次提问都包含推荐选项、推荐依据和可调整范围，帮助用户完成需求、脚本、声音、分镜、风格、素材范围和预览决策。
- 让 AI 根据内容密度、配音节奏、平台规格和素材条件自行判断内容正确性、镜头数量和插画比例。
- 一个正常项目只创建三个媒体生产 Agent：音频、图片和视频；每个 Agent 负责对应媒体的整批产物。
- 另外创建两个专用分析/设计 Agent：关键词时间 Agent、风格与动效 Agent。正常项目合计五个全新委派 Agent。
- 用一个轻量 `workflow.json` 保存恢复工作所需的最少事实。
- 失败时及时说明影响并给出下一步推荐，让用户直接决定重试、更换方案、补充资源或跳过。

### 2.2 产品边界

- 项目状态只记录恢复制作所需的选择、路径和下一步动作。
- 用户的四次确认是创意方向和交付范围的最终依据。
- 每种媒体按整批生产，一个正常项目使用固定、易理解的 Agent 分工。
- 生产结果以成功产物、失败项目和文件路径交接，主任务据此继续引导用户。
- 先生成低成本预览，再由用户决定最终导出或定向重做。
- 仓库只包含驱动这套流程所需的 Skill、插件清单和项目模板。

## 3. 设计原则

### 3.1 推荐先于提问

主任务不得只抛出空白问题。每个用户决策点都应先给出一个推荐方案，并用一两句解释判断依据，同时允许用户直接接受或指定修改。

### 3.2 AI 负责初判，用户负责关键取舍

生成台词和分镜时，AI 自行判断：

- 内容是否准确、完整并适合口播；
- 需要多少镜头；
- 每个镜头使用插画、文字动效、界面素材、用户素材或混合构图；
- 整体插画比例；
- 哪些信息需要在真实配音时间点出现。

单个镜头默认持续 3–5 秒。镜头超过 5 秒时，必须通过丰富动效、构图变化或持续的信息推进维持节奏；否则应拆镜头。

主任务应把判断依据一起展示给用户，例如“配音在 18 秒内包含三个概念，因此推荐拆为四个镜头”。用户可以直接接受，也可以只修改其中一项。

### 3.3 先预览，后导出

视频 Agent 在资产具备后优先生成可观看的低成本预览。用户确认预览后才执行最终导出。局部问题应进入定向重做，不回滚或重跑整个项目。

## 4. Skill 架构

V2 包含七个轻量 Skill。`video-director-v2` 同时承接预览后的用户选择，让用户始终从同一个入口完成下一步决策。

插件 manifest、Skill frontmatter 和界面文案统一采用正向描述：说明它会依据哪些事实给出什么推荐、帮助用户做什么选择，以及会产出什么结果。对外描述不提历史版本、被删除的机制或内部实现负担。

### 4.1 `video-director-v2`

主入口和项目编排器，运行在主任务中。负责：

- 引导需求并给出推荐方案；
- 生成、修改和确认台词脚本；
- 引导声音选择；
- 创建和更新 `workflow.json`；
- 按依赖关系委派五个全新 Agent；
- 汇总生产 Agent 返回的成功产物、失败项目和路径；
- 在四个用户决策点暂停；
- 处理预览反馈、最终导出选择和定向重做请求。

它以生产 Agent 报告的成功产物、失败项目和路径作为下一轮引导依据。

### 4.2 `voice-producer-v2`

供全新的音频 Agent 使用。一次接收已批准的完整台词和声音选择，负责全部配音生成，并返回：

- 成功音频路径；
- 每句配音的起止时间与时长；
- 总时长；
- 失败句目及失败原因。

同一音频 Agent 处理整份台词，不按句创建 Agent。

### 4.3 `keyword-timing-v2`

供全新的关键词时间 Agent 使用。它只在真实音频生成后启动，读取音频及句级时长，记录：

- 关键词；
- 重点数字；
- 关键短语；
- 问题与转折；
- 对应的毫秒级出现时间或时间区间；
- 建议关联的动效意图。

输出用于主任务的分镜设计和视频 Agent 的动效同步；台词版本和媒体生产继续由各自负责方管理。

### 4.4 `storyboard-director-v2`

由主任务直接使用。它根据已确认台词、真实配音时长和关键词时间完成：

- 镜头拆分与时长分配；
- 每个镜头的画面内容和信息层级；
- 关键动效出现时间；
- 插画数量、比例和资源范围；
- 超过 5 秒镜头的持续动效设计；
- 面向用户的推荐分镜方案。

用户在此阶段确认分镜、关键动效时间、插画数量及资源范围。

### 4.5 `visual-style-v2`

供全新的风格与动效 Agent 使用。它只在分镜确认后启动，负责生成：

- 一套推荐视觉方向；
- 必要的候选风格；
- 代表画面样例；
- 代表动效样例或可观看的短预览；
- 对图片 Agent 和视频 Agent 可直接使用的风格/动效说明。

这一阶段只生产确认方向所需的有限代表样例，不提前生成整批素材。用户必须确认风格与动效代表样例后，图片批量生产才能开始。

### 4.6 `illustration-producer-v2`

供全新的图片 Agent 使用。一次接收已确认分镜、风格和资源范围，负责整批插画生成。同一 Agent 持续处理整批图片，以维持角色、构图语言和画风一致。

返回成功图片路径、失败图片项目和原因。同一 Agent 负责整批图片，以维持一致性。

### 4.7 `remotion-video-v2`

供全新的视频 Agent 使用。它在音频、关键词时间和所需图片完成后启动，负责：

- 创建 Remotion 工程；
- 放置配音和插画；
- 生成字幕；
- 按关键词时间同步关键动效；
- 实现镜头内动效与转场；
- 优先生成预览；
- 在用户批准后执行最终导出。

它返回工程、预览、导出文件路径及失败项，供主任务继续引导用户选择导出或定向重做。

## 5. 正常项目流程

1. 主任务引导需求，生成推荐台词脚本和声音选择。
2. 用户确认决策点 1：台词脚本与声音。
3. 主任务创建全新的音频 Agent；音频 Agent 批量生成全部配音并记录真实时长。
4. 音频完成后，主任务创建全新的关键词时间 Agent；该 Agent 基于真实音频输出毫秒级关键词时间。
5. 主任务使用 `storyboard-director-v2` 设计分镜、关键动效时间、插画数量和资源范围。
6. 用户确认决策点 2：分镜、关键动效时间、插画数量及资源范围。
7. 主任务创建全新的风格与动效 Agent，生成代表画面和动效样例。
8. 用户确认决策点 3：风格与动效代表样例。
9. 主任务创建全新的图片 Agent；同一 Agent 批量完成全部插画。
10. 音频、关键词时间和图片均完成后，主任务创建全新的视频 Agent；视频 Agent 创建 Remotion 工程、字幕、动效和低成本预览。
11. 用户确认决策点 4：导出、局部修改或指定重做。
12. 用户选择导出时，由当前视频 Agent 执行最终导出；用户选择重做时，按第 8 节创建新的定向 Agent。

依赖顺序是硬边界：关键词时间依赖真实音频；风格与动效依赖已确认分镜；图片依赖已确认风格；视频依赖音频、关键词时间和所需图片。除此之外不增加等待节点。

## 6. 四个用户决策点

### 决策点 1：台词与声音

主任务展示推荐台词、预计时长、推荐声音及简短理由。用户可以确认、改文案或换声音。

### 决策点 2：分镜与素材范围

主任务展示推荐镜头表，至少包含镜头时长、配音范围、关键动效时间、视觉载体、插画需求和可使用资源。用户可以整体确认或逐项调整。

### 决策点 3：风格与代表动效

主任务展示推荐风格、代表画面和代表动效。用户确认后才允许批量出图。

### 决策点 4：视频预览

主任务展示预览路径并提供三个明确选项：最终导出、局部修改、指定媒体重做。默认推荐取决于用户反馈，不预设必须导出。

## 7. `workflow.json`

每个视频项目维护一个轻量 `workflow.json`，用于让主任务在恢复会话时快速找到当前选择、产物和下一步。

仅保存：

- 当前阶段；
- 已确认的用户选择；
- 台词、分镜、音频、关键词时间、图片、Remotion 工程、预览和成片路径；
- 当前待用户决定事项；
- 下一步动作。

推荐形状：

```json
{
  "stage": "awaiting_style_approval",
  "confirmed": {
    "script": true,
    "voice": true,
    "storyboard": true,
    "style": false,
    "preview": false
  },
  "paths": {
    "script": "script.md",
    "storyboard": "storyboard.md",
    "audio": ["audio/voiceover.wav"],
    "keywordTiming": "timing/keywords.json",
    "images": [],
    "remotionProject": null,
    "preview": null,
    "export": null
  },
  "pendingDecision": "确认推荐风格与代表动效",
  "nextAction": "批准后创建新的图片 Agent"
}
```

字段保持最少且可读，不扩展为通用项目管理系统。

## 8. 局部修改与定向重做

用户要求局部修改时，主任务先判断是否需要重新生成媒体：

- 仅改文字、字幕样式、时间或 Remotion 动效：创建新的定向视频 Agent，只修改指定内容。
- 重做部分配音：创建新的定向音频 Agent，只生成指定句目；完成后创建新的关键词时间 Agent 更新受影响时间，再由新的定向视频 Agent 更新预览。
- 重做部分插画：创建新的定向图片 Agent，只生成指定图片，并携带已确认风格和必要的一致性参考；随后创建新的定向视频 Agent 替换对应素材。
- 重做风格：创建新的定向风格与动效 Agent；用户重新确认后，再为受影响图片和视频分别创建新的定向 Agent。

定向 Agent 不重做用户未指定、且不受依赖变化影响的内容。

## 9. 失败处理

- 瞬时故障允许原生产 Agent 自动重试一次。
- 第二次失败后立即返回主任务，报告失败项目、原因和已成功产物路径。
- 主任务向用户提供有推荐顺序的选项：重试、更换工具、补充资源、在可行时跳过。
- 等待期间只在出现新产物、明确失败或需要用户决定时更新进度。
- 已成功的批次结果继续保留，不因局部失败而整体作废。

运行时只确认不可替代的事实：

- 音频确实生成且能读到时长；
- 图片文件确实生成并返回路径；
- Remotion 确实输出预览或成片。

这些事实由对应生产 Agent 在执行过程中获取并随结果一起返回。

## 11. 结果交接边界

仓库开发阶段通过一次性结构校验确认插件 manifest 和 Skill frontmatter 能被 Codex 读取。

实际视频项目中，媒体 Agent 返回成功产物、失败项目和文件路径；主任务立即把这些事实转化为用户可理解的下一步推荐。项目是否继续由四个用户决策点决定。

## 12. 完成标准

V2 达到可用状态时应满足：

- 能从用户主题或初稿开始，通过推荐式引导完成四个决策点；
- 一个正常项目最多创建三个媒体生产 Agent 和两个分析/设计 Agent，不按镜头或资产扩散；
- 配音真实时长能够驱动关键词时间、分镜和动效同步；
- 用户确认风格后才开始整批出图；
- 视频 Agent 在最终导出前先提供可观看预览；
- 任一生产失败在一次重试后立即给出下一步推荐并回到用户决策；
- 局部重做只影响指定媒体及必要下游依赖；
- 插件和每个 Skill 的对外描述都以“推荐依据、用户引导和可见产出”为中心。
